# vercel deploy --help
<claude-code-hint v="1" type="plugin" value="vercel@claude-plugins-official" />
Vercel CLI 65.16.0
▲ vercel deploy [project-path] [options]
Deploy your project to Vercel. Use `--temporary` to create a temporary
deployment without logging in. The `deploy` command is the default command for
the Vercel CLI, and can be omitted (`vc deploy my-app` equals `vc my-app`). Use
`--dry` to inspect the detected framework preset and source files without
deploying.

Options:
  --archive <FORMAT>                 Compress the deployment code into an
                                     archive before uploading it
  --build-env <KEY=VALUE>            Specify environment variables during
                                     build-time (e.g. `--build-env KEY1=value1
                                     --build-env KEY2=value2`)
  --create-if-missing                Create the --project if it doesn't exist
                                     yet. Needed only when --project names a new
                                     project with --yes or in non-interactive
                                     mode. Can't be used with --dry
  --delete-project-after <DURATION>  Create a temporary project that is deleted
                                     automatically after 1h, 1d, 1w, 2w, or 30d.
                                     Only applies when the deploy creates the
                                     project
  --dry                              Inspect the detected framework preset and
                                     source files without uploading or creating
                                     a deployment. Non-TTY output includes every
                                     file as JSON
  --env <KEY=VALUE>                  Specify environment variables during
                                     run-time (e.g. `--env KEY1=value1 --env
                                     KEY2=value2`)
  --environment <ENVIRONMENT>        Environment to deploy to: production,
                                     preview, or a custom environment
  --force                            Force a new deployment even if nothing has
                                     changed
  --guidance                         Receive command suggestions once deployment
                                     is complete
  --json                             Output as JSON
  --logs                             Print the build logs
  --meta <KEY=VALUE>                 Specify metadata for the deployment (e.g.
                                     `--meta KEY1=value1 --meta KEY2=value2`)
  --no-wait                          Don't wait for the deployment to finish
  --prebuilt                         Use in combination with `vc build`. Deploy
                                     an existing build
  --prod                             Create a production deployment (shorthand
                                     for `--environment production`)
  -p, --project <NAME_OR_ID>         Project name or ID to deploy to, without
                                     linking this directory (default: linked
                                     project). A missing name is created; with
                                     --yes or in non-interactive mode, add
                                     --create-if-missing
  --regions <REGION>                 Set default regions to enable the
                                     deployment on
  --skip-domain                      Disable the automatic promotion (aliasing)
                                     of the relevant domains to a new production
                                     deployment. You can use `vc promote` to
                                     complete the domain-assignment process
                                     later
  --temporary                        Create a temporary deployment without
                                     logging in. When logged in, use
                                     `--delete-project-after` instead
  --turbo                            Use a Turbo build machine for this
                                     deployment
  --verify                           Load the deployment URL once it is ready
                                     and report the status code, size, and page
                                     title, even with Deployment Protection on
                                     (creates the project's Protection Bypass
                                     for Automation secret if missing). Exits 1
                                     if the load fails. Can't be used with
                                     --no-wait or --dry
  --with-cache                       Retain build cache when using "--force"
  -y, --yes                          Use default options to skip all prompts

Global Options: See `vercel --help`

Examples:
  Deploy the current directory
    vercel

  Deploy a single HTML file
    vercel ./index.html

  Deploy a custom path
    vercel /usr/src/project

  Deploy to production and check that the URL loads
    vercel deploy --prod --verify

  Deploy with run-time Environment Variables
    vercel --env NODE_ENV=production

  Deploy with prebuilt outputs
    vercel build
    vercel deploy --prebuilt

  Deploy using a Turbo build machine
    vercel deploy --turbo

  Inspect deployment inputs without deploying
    vercel deploy --dry

  Get every deployment file as JSON
    vercel deploy --dry --json

  Write Deployment URL to a file
    vercel > deployment-url.txt

Vercel CLI 65.16.0
▲ vercel link [command] [options]
Link a local directory to a Vercel project

Commands:
  add  Add projects to an existing repository link created by link --repo

Options:
  --json                      Output as JSON
  -p, --project <NAME_OR_ID>  Set the project name or ID to link; required for
                              non-interactive existing-project links
  --repo                      Link multiple projects from the Git repository
                              (alpha; per-directory project links take

  -y, --yes                   Skip questions when setting up with default team
                              and settings

Global Options: See `vercel --help`

  Link current directory to a Vercel project
    vercel link

  Link current directory with default options and skip questions
    vercel link --yes

  Link to an existing project in CI or agent mode
    vercel link --yes --scope <TEAM> --project <project-name-or-id>

  Link a specific directory to a Vercel project
    vercel link --cwd /path/to/project

  Link multiple projects from the current Git repository
    vercel link --repo

  Add additional projects to an existing repository link
    vercel link add

<claude-code-hint v="1" type="plugin" value="vercel@claude-plugins-official" />
Vercel CLI 65.16.0
▲ vercel inspect <deployment> [options]
Show information about a deployment.

Options:
  --json            Output as JSON
  --logs            Prints the build logs instead of the deployment summary
  --timeout <TIME>  Time to wait for deployment completion (default: 3m)
  --wait            Blocks until deployment completes (exits 1 if --timeout is
                    reached first)

Global Options: See `vercel --help`

Examples:
  Get information about a deployment by its unique URL
    vercel inspect my-deployment-ji2fjij2.vercel.app

  Get information about the deployment an alias points to
    vercel inspect my-deployment.vercel.app

  Get information about a deployment by piping in the URL
    echo my-deployment.vercel.app | vercel inspect

  Wait up to 90 seconds for deployment to complete
    vercel inspect my-deployment.vercel.app --wait --timeout 90s

  Get deployment build logs
    vercel inspect my-deployment.vercel.app --logs

  Get deployment information as JSON
    vercel inspect my-deployment.vercel.app --json

<claude-code-hint v="1" type="plugin" value="vercel@claude-plugins-official" />
Vercel CLI 65.16.0
▲ vercel list [app] [options]
List deployments.

Options:
  -a, --all                        List resources across all projects
  -e, --environment <ENVIRONMENT>  Filter deployments by environment
  --json                           Output as JSON
  -n, --limit <NUMBER>             Number of results to return per page
                                   (default: 20, max: 100)
  --meta <KEY=VALUE>               Filter deployments by metadata (e.g. `--meta
                                   KEY=value`). Can appear many times.
  --next <CURSOR>                  Show the next page using the cursor from the
                                   previous output
  --policy <KEY=VALUE>             See deployments with provided Deployment
                                   Retention policies (e.g. `--policy
                                   KEY=value`). Can appear many times.
  --status <STATUS>                Filter deployments by their status. Can be
                                   comma-separated for multiple statuses (e.g.:
                                   `--status BUILDING,READY`)
  -y, --yes                        Accept default value for all prompts

Global Options: See `vercel --help`

Examples:
  List all deployments for the currently linked project
    vercel list

  List all deployments across all projects
    vercel list --all

  List all deployments for the project `my-app`
    vercel list my-app

  Filter deployments by metadata
    vercel list --meta key1=value1 --meta key2=value2

  Show the next page, using the cursor from the previous output
    vercel list my-app --next <CURSOR>

  Filter deployments by status
    vercel list --status READY

  Filter deployments by multiple statuses
    vercel list --status BUILDING,ERROR

# vercel curl --help
<claude-code-hint v="1" type="plugin" value="vercel@claude-plugins-official" />
Vercel CLI 65.16.0
▲ vercel curl <path> [options]
Make curl requests to Vercel deployments with automatic protection bypass.

Options:
  --deployment <DEPLOYMENT>     The deployment ID or URL to target
  --json                        With --trace, emit { response, requestId } as
                                JSON on stdout
  --protection-bypass <SECRET>  Protection bypass secret for accessing protected
                                deployments
  --trace                       Capture a session trace for the request and
                                print the trace request id
  -y, --yes                     Skip confirmation when linking is required (e.g.
                                in non-interactive mode)

Global Options: See `vercel --help`

Examples:
  Access a protected deployment URL
    vercel curl https://your-project-abc123.vercel.app/api/hello

  Make a GET request to an API endpoint
    vercel curl /api/hello

  Make a POST request with data
    vercel curl /api/users -- --request POST --data '{"name": "John"}'

  Target a specific deployment by ID
    vercel curl /api/status --deployment ERiL45NJvP8ghWxgbvCM447bmxwV

  Target a specific deployment by URL
    vercel curl /api/status --deployment https://your-project-abc123.vercel.app

  Use curl options after the separator
    vercel curl /api/test -- --header "Content-Type: application/json" --request PUT

  Use with protection bypass secret
    vercel curl /api/protected --protection-bypass <secret> -- --request GET

  Capture a session trace for the request
    vercel curl --trace /api/hello
